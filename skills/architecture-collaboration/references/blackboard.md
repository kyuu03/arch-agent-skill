# 共享黑板与项目接续

## 当前版入口与权威状态

长期项目的黑板首页指向当前大清单、父版/近期差异、真实成果版本及当轮重点。大清单持续验收与继承规则见[requirements.md](requirements.md)。黑板是恢复视图，完成状态来自总账及对应任务/检查，不能因不断追加“最新”段落而形成多个冲突的活动状态。

大清单保留稳定ID和全部有效要求；详细任务结束不移除整体验收要点。日常读当前完整版本及相关证据，来源冲突才回查历史。新反馈和相关修改可使已检查要点需要重验，助手判断与用户评价分别记录。旧黑板保留为历史入口；有效的授权与要求先纳入当前版再精简首页。

## 存储与启动

先查项目已有记录、成果目录及用户指定入口，沿用可用结构。需要新建时，可在项目内用 `.design-collaboration/blackboard.md` 作轻量入口，较大的证据与成果用链接引用。按实际工作量选择Markdown或结构化文件，无须先部署数据库或常驻服务。

黑板在项目内；个人知识与经验在使用者选择的外部位置。本地运行配置保存这些绑定，便于换项目、换使用者和接续工作。共享技能包只包含方法及字段约定，不写死个人绝对路径。

首次没有个人库时，记录“尚未绑定或尚无已核资料”，使用当前提供的项目材料继续可做的工作。必要的未知条件进入问题队列；不能把空库当作已研读，也不能默认要求用户先建设完整资料库。

## 最小黑板

按需维护以下内容，等价的既有格式无需迁移：

| 区域 | 内容 |
| --- | --- |
| 项目与目标 | 本轮阶段、用户原话、优先目标、适用条件、既定约束和授权范围 |
| 资料入口 | 用户库、专家目录、规范来源、当前图纸模型、报告与实际版本 |
| 问题与依赖 | 当前疑问、前提、可立即讨论的决策、需要查证的事实、受影响空间 |
| 专家任务 | 任务、身份、输入版本、读写范围、状态及结果入口 |
| 证据与候选 | 发现、解释、方案、出处、不确定性与反例 |
| 决定与分歧 | 已确认内容、讨论中的选择、理由、影响、未采纳意见及后续触发条件 |
| 修改与复核 | 具体改动、成果版本、相关问题、检查范围、结果与尚未闭合项 |
| 接续 | 当前可审看的成果、未解决事项、下一步及其必要输入 |

保留重要信息变化，无需把每条过程输出完整抄写到黑板。黑板应足以让下一轮恢复设计事实及判断依据。

首次需要落盘时，可从下面的短模板起步，按实际任务增减；完整字段约定用于补充必要信息。

```markdown
# 项目黑板

## 本轮目标与阶段
记录用户原话、当前阶段、已确认方向和工作边界。

## 资料与当前成果
记录真实版本、原始资料、个人库绑定及本轮可审看成果的入口。

## 证据、问题与候选
逐项注明来源、身份、状态、依赖，以及谁在何处受到什么影响。

## 决定、修改与复核
区分已确认、已实现和已验证，记录重要理由及检查范围。

## 接续与经验
保留未解决事项、明确下一步及本轮有条件的认识。
```

相对路径从记录所在文件的目录解析，包含表格、行内代码中的资料入口和普通链接。写入后核对关键原始资料与成果入口确实可打开；原始资料在上级或相邻目录时，验证目录层级。共享时另行维护可迁移路径，不能只检查可点击的Markdown链接而漏掉其他证据引用。

## 条目语义

对关键条目标记身份和状态：

- 身份：`用户原话 / 原作或条文 / 当前观察 / 解释 / 假设 / 候选 / 决定 / 经验`。
- 基础信息：简短ID、内容、来源、适用范围、关联空间或成果版本。
- 问题状态：`待核 / 已确认 / 已修改 / 复核通过 / 保留并说明原因 / 被后续证据替代`。

“候选”“推荐”“已确认”“已实现”“已验证”分别记录。用户要求先研读时，不将其回复解释为已接受某种具体设计动作。

## 更新与协同

专家将研究和建议写到各自任务结果，或其被分配的黑板区；总控整合权威项目状态。并行任务避免同时改同一模型、图纸或状态文件。需要共同编辑时先明确所有权与整合顺序。

重要决定链接到其证据、受影响的空间及后续检查；发现相互冲突的依据时，保存分歧并查清前提。用户明确的最新方向更新活动状态；旧状态保留为带背景的历史记录。

版本使用已有的模型版本、提交号或可辨认的文件标识。专家回报必须说明所查版本。修改后检查哪些结论仍适用、哪些已过期；不能以旧版本的通过报告认定新模型已通过。

## 审美与技术的不同证据

分别维护实际使用、空间体验与美感、技术规范、模型交付一致性的结论。统计、几何、性能和代码检查只支持对应事实；需要人视、平剖或真实网页判断的事项，安排直接审看。

复审以当前任务和受影响领域为范围。问题反复出现时查找根因，变更假设或方法，再比较实际结果；只有表现一致的结果才能进入已复核状态。

## 中断、恢复与交付

恢复时读目标、最新决定、真实成果身份、未闭合项和下一步；必要时核对文件现状。早期资料可作线索，不能覆盖新版本。资料找不到时说明具体缺口，继续不依赖它的工作。

交付展示可审看的设计成果、重要依据、真实变化和未解决条件。说明哪些意见已落实、哪些检查未完成。下轮从明确状态继续，不重新启动已经达成共识的普通工作授权。
