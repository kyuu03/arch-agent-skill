# 按问题派工、培养与系统复评

用于跨专业任务、反复失败、阶段交付或用户要求系统评估时。普通小改可直接完成；按实际必要程度记录，不为每次调用建立全套表格。沿用已有个人库和项目记录结构，不要求迁库或安装编排框架。

## 匹配与责任

将一个问题拆到可检查成果，固定输入版本和结束条件。分别评估并写理由：

| 判断 | 要回答什么 |
| --- | --- |
| 问题相关度 | 该角色能直接解决、支持、复核什么，或为何无关？ |
| 任务证据能力 | 哪些原始资料、实际应用和复核支持其承担这项任务？缺口限制了什么？ |
| 专业接口影响 | 结果会影响哪些使用、构造、技术、运营和表达接口？ |
| 独立复核需要 | 哪些结论需要另一个责任人直接看原始成果或重算，何时进行？ |

先用有理由的分级，按实际派工效果校准。资料不足、强制适用要求、必要复核分别设门槛，不用一个总分抵消。资料检索得分不等于专家胜任度。

分配主责解决者、必要协作者、研究任务及独立审查者，记录暂不调用的理由。已有原作可复用，不为大师名册每人生成一轮意见。研究可以产生设计候选，专业设计者承担具体方案；审查按成果依赖稍后启动，不持续空等。独立过程依靠原始证据、不同检查和重新计算，换名称不能保证消除共同偏差。

## 任务包与状态

任务包补充关联的大清单稳定ID、当前要求版本、所改变的成果版本及预计影响的其他要点。任务的`done`只结束本任务；不能据此把持续验收要点永久关闭。研究、实现和独立复核分别交付，旧版本通过不自动适用新版本。阶段汇合按[requirements.md](requirements.md)检查有效总要求覆盖，说明待复核影响与用户评价状态。

模型工具执行另按[verification.md](verification.md)写实时上下文、真实工具白名单、读写范围、预演能力、读回字段和授权来源。持久化恢复不能盲重放写操作；在提交后尚未保存检查点的窗口也须核实际结果再重试。

长期档案与当次执行分开。执行者默认接收最小任务包、必要原始材料定位及相关历史；需要完整条文/图面时仍读完整相关部分，超出范围说明补读原因。不默认继承全历史或汇总全部专家输出。

任务包至少明确：问题、目标成果、输入版本、职责、依赖、证据范围、写入范围、检查方式和停止条件。区分定位、候选设计、实现和复核；定位已达缺证边界时先落盘，不继续追加细部设计。较长任务先保存最小可用交付，再决定是否开新块。

状态可沿用当地等价定义：待依赖、执行中、已交付、已复核、缺证收口、失败/重定义。缺证收口完成的是当前交付，原设计问题仍开放；依赖它的设计/实现不得自动解锁。允许审查或研究明确接收缺证成果，检查边界或取得缺失输入。

完成后先保存并读回必要文件，再推进依赖；按本轮已激活任务汇合，不等待未调用的长期角色。并行成果按任务/角色分开存，总控综合，避免覆盖一个共享结论。

## 成本与停止

按问题规模限定尝试、追加检查、输出或时间范围；原生工具不支持强制限额时据实记为软预算，由总控及时收口。定位尝试次数不等于后续细化已有上限。无新证据的重复失败应补研究、改任务或换方法，跨恢复记录累计轮次，不每次恢复清零。

为预算写清超限后的下一动作：先保存最小结果并读回，结束当前任务；若仍扩展，及时中断并保留检查点，必要细化另立任务。预算按定位、研究、复核各自交付制定，不复制同一停止条件；起止、工具时间和代理自报耗时分别标明，记录时间若晚于实际派工也要注明。声明写入范围须与派工和实际目录一致，发现漏记或差异保留原痕迹再纠正。

结束状态包含可靠成果或明确的缺证/失败及最小后续证据；不为了凑肯定结论继续猜。用量能取得则记录真实数据，拿不到逐角色token时留空并标原因；辅助看实际调用/重试、材料规模、重复读取、时长和返工。减少展示文字或隐藏输出不代表减少模型调用。

一次必要复核即使没有新问题也有价值；建议未采纳也可能排除错误路线。少量明确问题的探索和能力培养可以安排，分别记录目的、投入与待验证结果，不强迫所有学习立即产生成品，也不让当前交付无限变成读书。

## 系统评估顾问

在新反馈、反复失败、跨专业接口变化、阶段成果或系统试跑触发。顾问检查覆盖遗漏、职责/粒度、证据能力、重复、等待、返工和投入是否相称，也检查总控的调度和自身成本。

顾问可提交有证据的复评要求，以及增设、拆分、合并、暂停角色、补研究或补独立复核建议。总控明确回应并执行，重要目标和代价取舍交用户；不用投票转移综合责任。保留原角色资料，暂停调用不等于删除知识。

以实际设计问题是否解决、原始资料能否追溯、使用/美感/技术检查、重复返工及投入共同判断。一次程序通过或专家数量不证明质量；顾问不是每次小改的常驻会议。每轮复评说明什么新证据或接口需要改变，给具体交付与停止条件。

## 能力与资料

具体能力可标研究中、有限试用、有验证支持，绑定原始资料、实际核读范围、应用/复核、反馈失败、适用限制和日期。读完一本书证明相应阅读，不能直接升为领域胜任；一次成功也不自动成为普遍方法。证据变化时可以修订或退回研究。

资料需求绑定一个问题，列准确来源/版本、所解问题、优先级、取得与核读方式、替代资料、负责角色和验收范围。先查已有资料和可自取来源，需要用户协助的电子书集中列出；已取得未读与已核读分开，不能把索书本身当知识。

## 可选记录检查器

当本地已有结构化记录或需要反复核验时，可运行：

```text
python scripts/check_run.py --registry <external-experts.json> --run <external-run.json> --out <external-check.json>
```

路径相对于对应JSON所在目录，绝对路径亦可。最小字段约定：

- registry：`sources[{id,path}]`；`experts[{id,capabilities[{id,status,evidence:[source-id]}]}]`。证据是能力的来源入口，不是自动可信证明。
- run：`scope/stopCondition/status/maxRounds/roundsUsed`；`inputs[{path,sha256?}]`；`assessments[{id,expert,relevance,evidenceCapability,interfaceImpact,reviewNeed,decision,decisionReason}]`，四项判断各有`grade/reason`；`tasks`按下述字段记录。
- task：`id/expert/capability/assessment/purpose/dependsOn/status/deliverable/writeScope/stopCondition`；产物`artifacts[{path,sha256?}]`与`outcome`；缺证加`evidenceGap`。审查用`reviewOf/independenceMethod`；明确接收缺证前序用`acceptEvidenceGapFrom:[task-id]`。
- 执行决定：`now/after-dependency/research-first/skip`。任务状态：`planned/running/delivered/done/needs-evidence/blocked/failed`。待审交付不能当复核完成。
- 设计问题关闭须另有`designIssueStatus=closed`、`uniqueObjectLocated`、`technicalAndExperienceVerified`及相关审查`reviewVerdict=accepted`；这些声明仍需实际证据支持。

检查器只验证声明契约、文件身份、依赖和状态一致性，不执行代理、不拦截未登记工具调用、不评价原作可信度、专家能力、规范与美感。运行结果不能替代领域审查；缺失真实数据不伪造填满。
