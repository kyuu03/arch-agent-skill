# 可执行核验与工具采用

在引入需求工程工具、模型规则、受控执行或持久化编排时读取。本文件区分验收语义与工具实现；外部建议是待核输入，不自动成为已证知识或项目硬要求。

## 验收方法与门槛

为可检查的子要求说明触发条件、对象/工况、可观测结果、测量或判断方法、证据和限制。EARS式句型可帮助表达，不能把“写成WHEN/SHALL”当作能够自动检查。空间体验仍须真实图面、人视和使用判断；定性要求不因难量化而删除。

Test、Inspection、Analysis、Demonstration、UserSignoff可作为方法标签。按每项真实需要选择，研究完成、任务完成、技术复核、体验判断、用户反馈不必全部成为每个要点的强制门槛。明确哪些门槛适用、由谁判断、如何验、依赖哪些成果；不适用给理由，缺记录不默认为通过。

父项不能只因全部子项有记录而自动通过；除适用子项外，还须检查父项自身的整体关系与跨项接口。记录覆盖、当前适用证据、验收就绪、用户评价和设计完成分别报告。G/USE/BRIEF/D/E/I是交叉类别，并非六层互不重复的叶子任务，不用“全绿条目/总条目”推导设计完成率。

## 规则的分工

- 需求工具检查ID、关系、格式、变更与追踪；不会自动理解自定义账本、知道历史遗漏或判定源材料真实性。外部导出保持只读派生，单一权威源仍需明确，往返转换须做ID与字段等价检查。
- IDS表达并检查IFC信息交付要求，例如实体、属性、分类、材料及关系等工具实际支持的条件。真实净宽、最不利疏散路径、几何碰撞、结构是否有支承、运营可行性和美感，须由适合的几何/工程/人工方法核验。属性数值存在不证明实际几何或整项合规。
- IFC语义差异可作为影响定位线索；先核导出配置、坐标、单位、GUID稳定性及表示变化。不稳定映射标未知，不将导出造成的重编号视为真实建筑全改，也不认为模型中没有的属性等于实际没有设施。
- BCF记录问题定位、视点和对象，可帮助回看，不单独证明问题正确或已解决。
- LLM可以起草条文映射、规则和报告；规则执行仅为被核过的输入、适用条文和算法给出有限范围结果。人工复核适用性、单位、条件、最不利工况和反例；不能用未经审查的自动规则取代工程事实。

## 执行契约

建模/绘图任务按工具实际能力填写：

1. `context_required`：实时文档/模型、视图、楼层、单位、坐标、版本/散列；恢复时重新发现，不默认沿用旧会话ID。
2. `tools_whitelist`：来自当前工具目录的真实调用名；能力缺失明确报告，不发明工具或未经授权退到任意代码执行。
3. `write_scope`：文件、对象、视图或参数边界；写前解析真实ID和预期旧值。
4. `execution_mode`：只读/预演/提交及支持程度；工具不支持事务或dry-run时明确局限，不宣称可回滚。预演不会自动升级为提交。
5. `readback_fields`：请求值、实际读回值、返回ID、警告、未能核验项。记录单位及读回来源，生成成功不等于保存/重开一致。
6. `authorization`：实际用户授权来源、适用范围和缺口；既有授权持续有效，普通可逆保存不一律增加确认。共享模型同步、不可逆覆盖等按具体权限与实际后果判断。

失败先核是否已提交，保留事务/操作ID和结果，再决定重试；不盲重放写操作。若引入LangGraph等工具，使用持久化checkpointer而非仅内存存储，按节点重放语义设计幂等操作、提交日志和读回；interrupt不是任意代码或外部写操作的安全边界。停止/恢复测试包含写入前、写入后未落检查点等不同故障窗口。

## 外部工具的采用条件

先定位官方仓库与具体版本，核实许可、格式、命令、支持范围及最小实际样例，再决定装配。第三方文章、星数、营销用时与模型数量不作验收依据。引用未定位的项目标为未核，不能虚构安装命令或引入其案例作为已验证经验。

按明确失败模式选择最小能力：先做隔离导出、断链/删项反例和只读样例；需要稳定工作后才扩大部署。日程估计与条目数量阈值仅为建议，按实际依赖与收益调整；不因到某周或达到某条数自动迁移平台、数据库或编排框架。
