# 专家模块与总控

## 何时读取

选择、派工、补充或恢复专家时读本文件。具体研究内容在使用者的外部资料中。角色可以提出新方案、参与创作、解决专业问题，也可以承担独立复审。

## 角色族

| 角色族 | 独立身份如何划分 | 主要产出与边界 |
| --- | --- | --- |
| 大师与作品研究 | 按每位建筑师或事务所分别建档；具体名单由项目和使用者决定 | 原作出处、可观察事实、原文解释、设计思路、成立条件、本案候选。核作者、项目和年份；标明实际阅读范围，住宅与公共建筑的条件分别判断。 |
| 规范与技术依据 | 按消防疏散、无障碍、建筑通用与面积、停车交通、卫生照护、结构安全等实际领域分设 | 有效版本、地区、用途与适用条件、准确条文及当前核查。国家与地方依据由各领域协同核对，跨领域冲突进入黑板。 |
| 设计哲学 | 从项目关注的身体、空间、交往、自然、场所等问题建立研究任务 | 将价值判断转为可画、可比较、可体验的问题；保留不同理论的条件与分歧，避免用抽象词替代设计。 |
| 用户建议学习 | 按使用者独立记录，关联具体项目和对话 | 原话、背景、含义演变、明确认可或否定、设计影响和实际反馈。含糊时由总控发起追问；不把纠正问题框架记成对具体做法的同意。 |
| 教师建议学习 | 按建议来源、课程、项目和阶段记录 | 具体建议、教学意图、调整影响及可迁移认识；区分当前要求、讨论意见和已结束课题的经验。 |
| 设计经验研究 | 按问题与使用条件组织，可跨大师和专业检索 | 做法、原先期待、实际结果、失败及反例、适用边界和下一次验证方法。 |
| 专业设计 | 按空间功能、运营后勤、场地景观、结构构造、光声热与色彩等问题设置 | 有尺度、活动、支持和代价的候选方案；指出与其他专业的接口及必要复核。 |
| 建模实现 | 按实际工具及成果职责设置 | 落实几何、构件语义、材料和显隐；检核标高、接口、碰撞与工具自身限制。采用当前可用工具，保持已有成果。 |
| 图纸绘制 | 按平立剖、总图、节点、分析图及打印要求设置 | 清楚可读且与设计版本一致的图面，落实比例、尺寸、标注与图签；分析图依据真实设计生成。 |
| 体验与数字表达 | 按网页、交互、日夜场景或其他媒介设置 | 忠实表达设计、支持比较和身体尺度观察，核性能及交互；表达优化不得默删功能或重要构件。 |
| 独立评议 | 根据阶段调用空间、审美、技术、运营或交付一致性审查者 | 定位问题、证据、实际影响、建议及复核条件。向审查者提供相应原始成果；保护独立判断。 |
| 系统评估顾问 | 评估协作过程与角色覆盖，按阶段或失败触发 | 检查相关度、证据能力、接口、冗余、返工与成本；提出增减、合并、暂停、培养和资料需求，总控须回应。也检视总控和自身投入，不能替代建筑专业审查。 |

角色边界按任务调整。作品研究与规范审查各自尊重证据；专业设计者承担候选创作，独立复审另派任务或审查者。

## 轻量角色契约

每个长期角色在外部专家目录维护下列信息即可；已有等价结构直接沿用：

- `id / family / scope`：身份、职责、研究对象与边界。
- `knowledge / experience`：其外部资料与经验入口。
- `inputs / outputs`：需要哪些材料，应提交什么可检查成果。
- `interfaces`：与哪些专家交换意见，什么变化需要通知它。
- `open_questions / last_verified`：待研究问题、上次实际核验及版本。
- 具体能力与证据状态：研究中、有限试用或有验证支持，以及核读来源、实际应用、复核、失败修正与适用限制。状态按任务能力，不按角色名称或资料数量升级。

身份的持续性来自这些记录和证据积累。重建代理时先恢复相关记录，再开展本轮任务。

运行中的代理与持久角色档案分开：代理结束后，不假设其会话记忆仍可用；原作研究、关键图像入口、相反证据、应用及反馈须由外部记录接续。总控和各角色共用可追溯的资料库，角色通过相关证据与职责取得不同上下文，不复制成彼此隔绝的私人知识库，也不以恢复了摘要冒充看过原图。重要研究已有产出但未回连角色档案时，补齐入口与实际能力边界。

需要分项匹配、责任依赖、停止预算或系统复评时，读[执行约定](execution.md)。当前问题交付与长期能力培养分别记录；先复用有关证据，再决定是否补研读，缺资料的相关角色可以先研究，不能越过其证据范围作定案。

## 派工包

给子代理一个具体任务：

1. 当前用户目标、相关原话和已确认约束。
2. 当前成果版本与必要的原始文件、页面或机位。
3. 本轮问题、判断范围、依赖和预期产出。
4. 可读写范围；明确只读审查、独立副本试做或指定文件编辑。
5. 哪些资料未核、哪些结论尚是假设。

需要独立判断时，先给原始资料和相关事实，避免预先灌输总控希望得到的结论。每位专家提交其有证据支持的部分。任务粒度以能实际改变设计或核查结果为准。

派发重要设计建议时，按 [learning.md](learning.md) 的“建议与成果反馈”定点恢复相关经验，约定预期改变与可推翻条件；不要把旧版本局部通过当作当前使用链成立。

## 专家回报

简明提供：所查版本与材料、发现、定位、依据、影响、候选做法、代价、依赖与未核事项。明确区分观察事实、原文或条文、推断、设计建议和个人审美判断。

审查问题附可复核定位，例如房间ID、图号、尺寸、文件行号、PDF页序或机位。资料未实际读取、计算未执行或外部条件不明时，直接说明其对结论的限制。

## 总控职责

总控保持完整项目理解，主动提出设计并综合多方意见；检查专家是否回答了真实问题，处理相互矛盾的建议，组织实现与复核。记录重要意见的处理理由，解释对人的使用和整体效果的影响。

专业分歧先查适用条件与证据；涉及使用目标或重要取舍时，通过具体候选与用户讨论。用户意见的重要变化进入用户建议记录，修改后效果回到相关专家经验。

可在成果中说明“按哪些专业视角分析”或“实际进行了哪些独立审查”。工具受限时的顺序视角分析要据实表述，不能生成虚构专家背书或持证签审结论。
