# 外部知识、经验与个人积累

## 独立的存储与共享

知识库、经验库和个人角色档案保存于使用者控制的外部位置，路径由项目绑定。它们可以是本地、个人所有且按选择共享的资料；这三个属性分别记录。本技能包不携带某位使用者的资料、私人偏好或项目事实。

共享框架与共享资料分别进行。只有用户选择共享时，整理相应条目及其来源、背景、版本和适用条件；保留在本地的资料不随技能复制。工具与文件访问继续遵守当前实际授权。

没有已有库的使用者可以从当前任务和反馈开始积累。先查已提供材料；缺少原作或规范时，指出尚未核实的结论，并据任务允许范围寻找可用依据或记录研究任务。每个人形成自己的资料、研究解释与经验。

## 知识条目

最小记录：主题/对象、来源与可核位置、实际阅读或计算范围、事实或原文、解释、适用条件、版本或核验日期、相关项目。

按大师/项目、规范领域/地区/用途、空间问题等可检索维度组织索引。允许多个专家引用同一原始来源，保留各自不同解释。来源缺页、OCR不可靠、标准时效或模型简化等限制跟随结论保存。

书籍及案例研究注明作者、项目、年代和原页；事实、作者解释与本案推断分开。规范条目记录地区、效力、版本、适用范围和相关条件；发生新任务、版本变化或依据冲突时复核，不能永久把某条标准标作适用于所有项目。

## 经验条目

最小记录：处境与问题、原先期待、实际做法、受影响者、用户或教师反馈、修改结果、证据、代价与反例、适用边界、验证状态、下次触发条件。

可用状态：`初步观察 / 待验证 / 有本案支持 / 有跨情境支持 / 已修订或失效`。一次成功或失败先作为带条件的案例；进一步使用后逐步提升可迁移程度。保留失败与被否定路径，防止重复尝试。

增补`decision_trace`记录先试什么、为何失败/被否定、后来如何改；`verified_at`标最近实际核验，`review_trigger/review_due`按条目性质记录复核触发或期限。不要给原作事实、项目决定、规范效力和产品/工具能力统一套30天失效。待复核与已证伪/失效分开，时间提醒不能自动删除原记录或取消要求。外部失败案例先保留来源与未核范围，不批量写成个人已验证经验；知识健康关注来源定位、矛盾、陈旧适用性与实际调用结果，不能用关系密度或条目数量代替质量。

## 用户与教师反馈

保存原话、来源、时间/阶段、讨论对象、含义变化、明确确认范围和落实结果。区分用户稳定偏好、暂时倾向、某案判断及尚未确认的建议。遇到新解释时修订理解，旧理解保留为历史而非活动约束。

教师建议还需记录课程和教学背景，提炼其解决问题的方法与适用条件。已结束作业的反馈按经验保留；后续项目是否采用由当前目标和条件判断。

## 专家与总控怎样进步

专家更新其原作研究、事实依据、设计方法和条件认识；总控更新问题定义、派工方式、综合判断及验证策略。每轮重要反馈至少对应一个具体后续影响：修改候选、调整专家任务、增加必要检查、改变评价方式或保留待验证假设。

检验“学会了什么”时，看下一次处理同类问题是否实际改变。记录数量、专家数量、角色名称和自称掌握均不证明学习效果。用户对体验的持续否定应触发重新诊断，而非继续引用同一技术通过报告。

按具体能力将原始资料、核读范围、应用、独立核对和反馈失败绑定到角色档案，允许能力状态随证据修订。资料缺口列准确来源、所解问题、优先级、获取/核读与验收方式；已取得未读不当作已掌握。按[执行约定](execution.md)由系统顾问评估补资料、培养或专家调整，知识与经验仍留在使用者的外部位置。

新认识写到适当层级：

- 本案决定写项目黑板及相关成果记录。
- 个人偏好与交流背景写使用者记录。
- 有出处的原作/条文/计算写知识条目。
- 实践得失与工作方法写有条件的经验条目或专家档案。

可复用框架的规则调整在技能维护任务中进行，避免把个人项目的临时做法静默固化到共享技能。真正有通用价值的改进保留证据、范围与版本，供维护时判断。

## 接续与迁移

### 与需求总账连接

知识条目回答“依据是什么”，经验条目回答“什么条件下做法有效或失败”，项目总账回答“当前仍须满足什么”。通过稳定要点ID及成果版本互相引用，不在知识库、经验库和黑板各复制一套完成状态。原始要求及用户决定与研究解释分别保存，研究建议不能自动升级成用户要求。

检索新任务时先读当前大清单及受影响要点，再取对应来源与经验；回流时记录该经验改变了什么任务、验收方式或候选。经验的适用条件变化、反例或来源失效时，关联的项目结论需重新判断。经验条目过期不自动取消项目要求。一次局部通过只支持相应版本与检查范围，不记为“此类问题永久解决”。

知识与经验可继续使用原有项目文件、数据库和个人库位置；用明确绑定文件记录当前入口和共享范围。没有真正同步到应用数据库时，说明仅新增文件索引，不声称网页已接入或跨项目自动学习。迁移先保留原记录及ID映射，并核对现有使用者；不要为改方法无关重写应用存储。

新一轮按当前问题检索相关记录，先读摘要、来源和条件，再按需打开原始材料。遇到矛盾检查来源、时间、地区、设计版本和原意；保留未解决分歧。

跨项目迁移时显式重新判断适用性。每位新使用者从自己的目标、资料和反馈建立个性化积累；共享来的条目仍保留原背景，不能自动继承原使用者的个人选择。
