# 工作轨迹

导航“工作轨迹”显示模块关系、按序回放、闪动方向线、事件证据和节点累计到达数。操作仍在对话，页面不派工、不执行包内指令。

在外部 local.config.json 加 `"run_log": "项目根目录相对路径.json"`，重新启动平台。日志与知识库、项目一样外置，本体不携带私人项目记录。未配置时显示未绑定，不生成虚构活动。

可选 `run_logs` 为日志路径数组；配置后页面可切换多次实验，`run_log` 指定默认项。历史重建和本次实际记账可并存，各自保留mode、时间和证据边界。

日志格式：schemaVersion=1，id、title、mode、limitations、modules、events。modules 每项含 id、title、kind、description，可选 executionsKnown（明确语义下的已知执行轮数）。events 每项含唯一 id、递增 sequence、from、to、title、detail、evidence 字符串数组、time（ISO时间或 null）、status、basis。from/to 引用模块ID。

mode=reconstructed 表示历史重建，逻辑事件可以归并多次工具操作，不能据此计算精确耗时、并发或完整调用次数。mode=recorded 也仅显示日志实际写入的事件，不意味着自动探测了代理活动。当前平台每5秒读取日志变化，无自动采集器；只有工作执行者实际写入开始、结束、失败等事件，才有相应观测证据。

节点 ×N 是当前步骤之前以该模块为目标的事件条数。点击模块查看全部相关事件及已知轮数。它不是工具调用次数、Token用量、完成率或验收通过率。用户提供的总用量不自动分摊模块。

方案二首个日志为14条逻辑事件的重建：研究专家实际激活一次；独立复核有初检及一次受影响复验。全部模块时间未知，不人为平均分配34分钟。最终模型局部改动未获独立验收。


## v0.3.0 可点击证据

events[].evidence 继续接受旧字符串（仅文字定位）；新增对象 `{ "path": "项目根相对路径", "label": "证据名称", "kind": "text", "sha256": "可选绑定散列" }`。path必须位于项目根内；文件可读取不代表结论已验收。点击事件证据可预览文本/JSON/图片及当前散列，与绑定散列不同会提示变化。HTML、模型等下载到本地应用查看，不在管理源执行；SVG作为源码预览。单文件上限32 MiB，文本预览前128 KiB。

接口 `GET /api/evidence?run=<绑定日志ID>&event=<事件ID>&index=<证据序号>` 只解析已配置日志的明确证据条目，不提供任意文件路径参数。mode=download下载文件，mode=image仅允许受支持图片类型。此功能为只读映射，不自动派工或自动验证学习能力。
