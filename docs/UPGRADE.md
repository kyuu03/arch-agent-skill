# 升级、迁移与回退

## 本体升级

1. 记录正在使用的程序版本、配置路径、数据路径和端口。
2. 停止服务，备份本机配置、项目记录、原知识目录、安装包与关键成果。不要只备份本体。
3. 在独立新目录检出新版，不覆盖旧版本，先读CHANGELOG和格式兼容说明。
4. 运行标准库测试、发布检查和虚构演示；确认不需要作者个人资料。
5. 使用真实绑定启动，检查总账版本、稳定ID、要求数量、关键负评、暂停任务、库条目和成果身份。
6. 新旧版本均可用时再修改自己的启动入口；保留旧程序和数据备份直到核验完成。

平台代码、全局安装的技能、本机配置、项目需求基线、模型版本、包格式、包内容版本是不同升级对象。不要用一个版本号替代所有身份。

## 资料包升级

内容变化用新version，先预览再安装。旧包不覆盖，v1也不自动选择最新版。当前没有网页禁用/卸载/依赖求解功能。若要替换显示范围，停服务后备份移走旧版本目录或调整只读挂载根，保留历史证据。

外部包不自动同步到旧工作台数据库，也不自动覆盖项目专家档案。跨项目使用时重新判断气候、地区、规范、运行模式和证据范围。

## 数据格式升级

配置仅支持schemaVersion=1，包仅支持ac-library-pack/v1。未知版本拒绝而不是猜测解析。未来迁移需：输入/输出格式明确、备份、试运行、原ID映射、字段损失报告、迁移后检查与回退说明。当前没有自动格式迁移器。

## 原目录整理

本地整理由索引与绑定开始，不物理挪动活跃模型、原书、总账和旧数据库。迁移索引记录源路径、大小和散列，是整理时快照，不是实时同步状态。文件后续改变会与快照不同，这是预期；重新核对而不是重绑历史证据散列。

真正搬迁应逐类进行：查引用→拷贝到目标→核对散列→更新相对/绝对绑定→验证旧工具和成果→再处理旧位置。不要只改可点击链接而遗漏JSON、行内代码、模型工具和资料源字段。

## 回退

停止新版，恢复原启动入口。若数据尚未变格式，可用旧版本连接同一份备份兼容数据；若已迁移，应同时恢复迁移前数据与配置。删除本体不应删除外部库；不要把数据目录放入会被重新解包或清理的程序目录。
