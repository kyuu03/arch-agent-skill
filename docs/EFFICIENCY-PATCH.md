# 技能投入控制补丁 — 2026-11-13

用户反馈：启用协作技能后，token消耗速度显著上升，很多投入没有意义。该反馈不是已测得的逐调用账单；本补丁没有据此宣称精确归因或节约比例。

## 修改

- 问答、路径指引、状态查看：直接处理，不派代理，不建立整套记录。
- 明确局部修改：相关对象及接口定点读取，默认单代理，一次相称验证。
- 整体实质变化与正式阶段验收：才展开必要跨专业研究和独立复核。
- 已读且未变化的资料复用；首次恢复、基线变化、冲突和整体验收才展开全账。
- 不沿参考链接递归全文读取，不把巨型文件和全部专家输出塞进上下文。
- 普通反馈不自动调用系统顾问；不为内部推敲模拟多轮grill问答。
- 代理仅在确有独立证据或时间收益时调用，传最小上下文，不默认全历史分叉。
- 验证通过后，无变化、失败或疑点不重复检查；无新证据的重复失败及时换方法。
- 重要状态批量回流；普通问答不制造来源、任务、复核三件套。

## 保留

持续要求、稳定ID、版本继承、用户否定、真实证据、受影响项复核和必要独立检查均保留。减少的是重复读取与形式性调度，不是删验收项或提前结束任务。

## 行为验收例

| 请求 | 预期路径 |
| --- | --- |
| “这个文件在哪？” | 已知就回答；未知定点查路径，无总账更新或派工 |
| “改一个按钮文字” | 读相关代码、修改、相称核对，不启动建筑整体验收 |
| “门改侧开” | 核相关门位、来路、扫掠与影响项，必要研究，不召集全部专家 |

| “继续，版本没变” | 复用可靠接续信息，查本轮增量，不重读全部原书和历史 |

## 0.3.1增补 — 2026-11-14

围绕实际复盘暴露的过早固定骨架、局部精度替代全局核查和派工收益不清，更新既有执行、核验与学习参考。个人项目、具体尺寸、token账单和用户评分仍留在外部库，没有写进公开技能。

- 总体尚未选定时先做少量低成本比较，组织不同而非只换表皮；用户已选方向或局部修改不重复发散。
- 反复局部修补不能改善整体时，允许质疑主张和骨架；保留必要功能能力，不自动冻结旧坐标，也不每轮推倒重来。
- 布局关键条件提前核查；条件不明可作有假设的候选，但不得凭形态认可宣称原整体目标达到。
- 默认总控推进，按独有产出、独立性、预计收益与开销决定派工；程序承担可靠的确定性工作，必要独立审查保留。
- 复用相关经验、程序和反证，实际质量、耗时与费用分别评估，不把缓存比例当免费比例。

### 更新后的行为验收例

| 情境 | 预期决策 |
| --- | --- |
| 整体方向尚未确定 | 以相同功能和关键条件比较少量不同组织，暂不将各翼详细实现全部并发 |
| 用户已选方向，只改一个房间 | 沿用已选组织，核本地接口，不强制新增总体方案或专家会议 |
| 两轮都靠加连廊补同一总体矛盾 | 先诊断组织假设与任务边界，再决定保留或改变骨架；不只换表皮 |
| 形态获好评，但交通接入和安全终点未成立 | 保留形态判断，明确整体关键缺口；继续必要核查或按真实上限交有条件候选，不记整体达标 |
| 有独立的规范研究和成熟出图程序 | 规范研究有明确收益时派工，程序直接运行，复核随成果依赖启动 |
| 用户报告价格较低、效果仍有差距 | 保留用户评价与比较条件，校准当前判断，不据token或主观百分比编造质量收益率 |

这些是可在下一任务观察的行为目标，未因结构验证通过就宣称已完成真实成本或质量对照实验。
