# 建筑设计与学习协作平台

**把持续需求、共享黑板、设计证据和个人积累连接起来。设计与派工继续在对话中，平台显示真实项目记录；知识与经验以外接目录或资料包接入。**

当前版本 **0.3.1**（本地待发布）。这是可本地运行、可继续升级的框架与文件平台，不是已经具备自动建筑设计、规范签审和环境仿真能力的系统。

**想知道如何用它做一份建筑作业、还需装哪些软件？** 请先看 [实际工作流实例与软件准备](docs/WORKFLOW-EXAMPLE.md)。该文以真实迭代过程为原型作匿名说明；公开本体没有附原项目模型、私人知识库及Revit/SU适配器，不能承诺安装后自动做出相同水平成果。

## 1. 发布范围和目录边界

本仓库应只来自本地整理目录中的 **`core/`**。上一级是个人装配区，`local-data/` 是私人资料与绑定，**不要把上一级作为要上传的仓库**。

```text
architecture-collaboration-release/  ← 本地装配区，不整体上传
├── core/                          ← 本 README 所在目录；作为 GitHub 仓库根目录
│   ├── app.py                     启动、初始化外部演示项目
│   ├── ac_platform/
│   │   ├── server.py              本机服务、配置与项目只读接口
│   │   ├── library.py             资料包校验、安装、选择导出
│   │   └── web/                   平台页面
│   ├── skills/architecture-collaboration/
│   │   ├── SKILL.md               对话协作入口
│   │   ├── agents/                技能显示信息
│   │   ├── references/            黑板、需求、经验、执行等约定
│   │   └── scripts/               总账、运行与追踪矩阵检查工具
│   ├── examples/                  仅虚构演示；无私人项目
│   ├── docs/                      数据格式、API、架构、升级与迁移细则
│   ├── tests/                     标准库单元测试
│   ├── tools/release_check.py     发布前检查与文件清单
│   ├── config.example.json        相对路径演示绑定
│   ├── VERSION / CHANGELOG.md
│   ├── NOTICE.md                  权利、依赖和发布许可说明
│   └── .gitignore
└── local-data/                    ← 不上传；本机配置、安装包与迁移索引
    ├── local.config.json          本人的项目绑定
    ├── project-records/           原总账、黑板、成果入口索引
    ├── knowledge-experience/      原资料库入口索引
    ├── legacy-workbench/          旧工作台兼容索引
    ├── migration-inventory.json   整理时的来源与散列清单
    └── storage/                   运行后产生的包和服务状态
```

这里的“本体”包含平台代码、技能框架、检查工具、格式文档和虚构示例；“库”包含个人资料、项目事实、反馈、角色积累和选择安装的资料包。项目事实与可迁移经验也要区分：项目决定仍在项目总账，不因进入经验库就成为其他项目的要求。

**当前发行物不包含旧设计工作台的全部源码。** 原工程存在案例、任务书、课程作业和硬编码路径耦合，不能把它直接当作无私人数据的通用程序上传。本版提供配置化兼容入口；旧工程和数据保持原位，既有功能没有被删除。详细边界见第8节。公开本体是“协作框架＋本地映射＋资料包管理”，不是对旧工程已完成全面通用化的声明。

## 2. 快速启动

### 2.1 环境

- Python **3.11 或更高版本**；仅使用标准库，无需 `pip install`。
- 现代浏览器；Windows、macOS、Linux 原则上均可运行。此版本实际检查环境为 Windows + Python 3.12 + Edge；其他系统没有逐台实测。
- **仅运行平台**无需 Node、npm、Revit、SketchUp、数据库、付费 API 或模型密钥。若要在对话中实际设计、建模、出图，仍需另配AI助手及相应软件/工具接口，见[软件准备表](docs/WORKFLOW-EXAMPLE.md#2-软件不是都要一次装齐)。
- `python` 应指向已安装的 Python；Windows 也可使用 `py -3`。

在本 README 所在目录运行：

```sh
python app.py
```

打开 **http://127.0.0.1:8850**。默认显示虚构项目，安装包写入仓库相邻的 `local-data/demo-storage/`，不会写回示例项目。

停止服务：在启动它的终端按 `Ctrl+C`。端口被占用时会明确报错，不会悄悄切换到另一个项目：

```sh
python app.py --port 8852
```

默认只监听 `127.0.0.1`。本版没有远程账号、多用户权限或公网部署设计，不要把它当作可直接暴露公网的服务器。

### 2.2 为自己的数据建立独立目录

```sh
python app.py --init-data ../my-architecture-data
python app.py --config ../my-architecture-data/local.config.json
```

初始化只接受**不存在的新目录**，避免覆盖已有资料。它复制虚构项目模板、写入新绑定；不复制当前使用者的个人项目，也不表示你已经有知识库。之后编辑这个外部目录中的项目资料及绑定配置。

本地整理版本可使用随本机创建的绑定：

```sh
python app.py --config ../local-data/local.config.json
```

这份本机配置不会随 `core/` 发布。其他人克隆仓库后应使用演示配置或初始化自己的外部目录。

### 2.3 第一次体验资料包

1. 进入“资料包管理”。
2. 选择 `examples/example-methods.acpack.json`。
3. 查看包ID、版本、作者、许可、条目、验证状态和散列；展开完整内容。
4. 确认安装。安装后的示例可在“知识与经验”中检索。
5. 在导出区只勾选需要的条目，填写新包的ID、版本、标题、作者和许可。
6. 生成预览，检查完整导出内容，再点击下载。

安装是写入外部库；没有执行包里的脚本，没有更改项目要求，也没有把“未验证”提升为“已验证”。

## 3. 页面及操作边界

| 页面 | 显示什么 | 权威来源 / 边界 |
| --- | --- | --- |
| 当前黑板 | 当前阶段、重点、决定、待核与接续 | 配置指定的黑板；它是恢复视图 |
| 本轮待办 | 当前可做、暂停或待依赖的工作 | 配置指定的清单；不独立维护完成状态 |
| 需求总账 | 持续要求、稳定ID、来源、关联任务和复核 | 当前完整总账；支持搜索和详情 |
| 任务与复核 | 任务状态、技术/体验/独立/用户反馈 | 总账中的任务及检查记录；不混算通过率 |
| 知识与经验 | 安装包及外部文本目录里的条目 | 保留来源、条件、原验证状态与共享标记 |
| 专家档案 | 当前项目的职责与能力范围 | 角色有名称不代表已运行代理或持证签审 |
| 迭代与流程 | 工作机制、父版、变化、待复核影响 | 展示文件里的记录，非实时编排监控 |
| 成果与兼容 | 配置白名单的成果下载与旧工作台入口 | 版本需显式标注；不自动判断同版 |
| 资料包管理 | 安装预览、确认安装、选择导出 | 只写外部安装目录；不写项目模型 |

平台每 **5秒**重新读取一次当前项目与外部资料；文件读取失败时显示中断并保留上次视图，不把缺失数据伪装为空库已通过。资料包管理页避免定时刷新打断填写；新装包的列表在切换页面后可查看。

设计操作、重要取舍、派工与模型修改继续在对话中进行。本体没有向 Codex 发送消息、自动创建代理、执行任意代码、控制 Revit、写 SU 或替用户签认的后台接口。页面不是第二个聊天模型。

项目 HTML 成果以下载方式提供，不在资料管理页面的同源环境执行任意成果脚本。下载后在合适环境另行打开。原有体验模型入口仍可沿旧项目交付索引使用。

## 4. 接入自己的项目

配置文件是本机入口，**路径均相对于配置文件所在目录**，不是相对于当前终端目录。`project_root`、`data_root`、外部库路径可用绝对路径，但这些配置应留在本地，不进入公开仓库。

```json
{
  "schemaVersion": 1,
  "title": "我的社区设计",
  "project_root": "project",
  "data_root": "storage",
  "ledger": "requirements/current.json",
  "blackboard": "blackboard.md",
  "checklist": "checklist.md",
  "experts": "experts.json",
  "notice": "当前仅研究；未授权实施的任务保持暂停。",
  "library_mounts": ["../shared-architecture-library"],
  "document_mounts": [
    {"id":"my-notes","title":"既有笔记","path":"notes","author":"资料所有者"}
  ],
  "artifacts": [
    {"title":"本轮说明","path":"deliverables/description.md","version":"design-v1","note":"不是正式规范签审"}
  ]
}
```

字段含义：

- `schemaVersion`：当前仅支持1；遇到不支持的版本应停止并迁移，不静默猜测。
- `project_root`：项目文件访问边界。总账、黑板、清单、角色和成果路径相对于它；路径不允许越过边界。
- `data_root`：安装包及运行状态的写入位置；与项目要求、模型分开。
- `ledger`：当前完整总账JSON，必填。
- `blackboard/checklist/experts`：可选绑定。缺失绑定显示“尚未绑定”，不假定已有资料。
- `library_mounts`：外部资料包根目录，可有多个；目录结构为 `包ID/版本/pack.json`，作为只读挂载。
- `document_mounts`：已有纯文本目录的实时读取适配，见第6节。不是任意程序插件。
- `artifacts`：允许下载的文件清单；未列入的工作区文件不会通过HTTP任意读取。
- `legacy`：可选兼容信息；仅允许格式为 `http://127.0.0.1:端口` 的旧工作台链接，不执行启动命令。

修改绑定后重启服务；项目文件内容与笔记内容则每5秒重新读取，无需重启。此版一个进程绑定一个项目；多项目可启动不同端口和不同配置，不共用写入目录。

## 5. 统一总账、黑板和迭代

### 5.1 为什么不是每轮另写一张“最新清单”

当前大清单完整继承上一版仍有效要求。新一轮只聚焦一部分任务，不能让前面的整体要求消失。稳定ID连接总目标、分项、详细任务、来源和验收。

- 要求变化：保留父版、快照、差异、理由和决定来源。
- 普通进度更新：更新任务与证据，不必另造大清单版本。
- 替代或取消：明确记录ID、理由与决定者；不能静默删除。
- 任务结束：仅代表本轮范围结束，持续验收要点仍在。
- 相关模型改动或新负评：保留旧证据，并使受影响结论需要复核。
- 用户评价、助手技术判断、助手体验判断和独立复核分开。
- 缺少当前版本证据：保留待核，不猜测已完成。

### 5.2 各层记录各司其职

```text
对话 / 用户反馈
      ↓ 明确范围与决定来源
当前完整需求总账 ← 父版 / 差异 / 稳定ID
      ↕
任务与成果版本 → 实际图面 / 模型 / 计算 → 分层复核
      ↓ 影响分析与新反馈
黑板恢复重点；知识保存依据；经验保留条件与失败路径
      ↓
下一轮继承有效要求，重新核查受影响项
```

平台只显示这些关系，不会凭“75条记录”“文件结构通过”或“局部子项完成”自动算出建筑整体验收通过。

### 5.3 检查工具

可复用工具位于 `skills/architecture-collaboration/scripts/`：

```sh
python skills/architecture-collaboration/scripts/check_requirements.py --ledger ../my-data/project/requirements/current.json --previous ../my-data/project/requirements/baseline-v1.json --out ../my-data/project/requirements/check.json --render ../my-data/project/requirements/current.md
```

`check_requirements.py` 核对ID、关系、版本、证据引用和继承等文件结构约束。输出 `structuralCheckPassed` **不等于**规范、安全、体验、美学或整体验收通过。

`export_traceability.py` 可生成需求与证据矩阵；验收方法映射是另外的配置，不会自动发明尚未配置的测试。参见其 `--help` 和 `references/verification.md`。

## 6. 知识经验库与资料包

### 6.1 库可以完全在本体外

两种接入方式可并存：

**A. 既有目录实时映射**：`document_mounts` 读取目录第一层的 `.md/.txt/.json/.mjs` 文本，每个文件最大128 KiB，不递归、不读取软链接、不运行JS。它将文件包装成可搜索的派生条目。文件原地保持权威；本体不改写它。

这种适配只识别文件名含“经验”为经验类，其他默认知识类；这是便于接续的粗分类，不是对内容身份的专业判定。条目一律标 `private/unverified`，意思是**适配器没有重新核验正文结论**，不抹去正文里已有的历史验证描述。原文件散列与路径随来源保留。超过限制或非UTF-8文件不会进入此轻量映射，原文件仍在。

**B. 标准资料包**：可搬到不同电脑或不同项目使用，类型包括知识、经验、专家条目。包是UTF-8 JSON，不带可执行安装器。安装后每个版本独立保存：

```text
data_root/libraries/
└── package-id/
    └── 1.0.0/
        └── pack.json
```

安装是增加一个资料来源，不是自动把别人经验变成自己的结论，也不会自动改写当前项目专家档案或总账。

### 6.2 安装规则

- 最大8 MiB，1–100个条目，每条正文最大128 KiB。
- 包必须有格式版本、ID、版本、标题、作者、许可、条目与SHA256。
- 同ID同版本同散列重复安装为无操作；同ID同版本不同内容拒绝覆盖。
- 升级包使用新版本；旧版保留。当前显示所有挂载/安装版本，**没有偷偷选择“最新版本”的自动激活逻辑**。
- 格式不支持、路径式ID、损坏散列、重复条目ID等会拒绝。
- 安装只写配置的数据目录，不修改项目、原文件或技能。
- 安装不执行包内指令；条目文本只是待判断的资料。

### 6.3 导出规则

1. 在页面勾选条目；不是默认全库导出。
2. 填写新包信息。许可是本次整理包的声明，不能撤销原条目已有许可。
3. 私人条目需明确勾选“已检查内容和分享权利”。这不会把原库标记改成公开。
4. 预览条目、来源、状态、作者链和散列，查看完整内容。
5. 确认下载 `.acpack.json`。

导出保留正文、来源、原验证状态和原包身份链；生成新的包内条目ID以避免不同库的ID冲突。不默认带原书PDF、图纸、模型、项目总账、聊天记录或API配置。文字本身仍可能含个人信息、绝对路径或不可再分发的摘录；自动提醒只是辅助，不能替代逐项检查。

导出预览可能提示私人条目、本机路径或类似凭据文字。默认私有条目不允许未经勾选确认导出。散列不等于数字签名，不验证作者身份，不证明内容正确。

### 6.4 知识与经验应写什么

知识建议保留：主题、来源、页码或可定位位置、实际阅读/计算范围、原文事实、作者解释、本案推断、适用条件、版本和核验日期。

经验建议保留：处境、原期待、实际做法、受影响者、反馈、结果、证据、代价、反例、适用边界、验证状态、失败路径与下次复核触发条件。

不统一给所有资料设30天失效。原作事实、项目决定、标准效力和工具能力各自有不同复核依据。“待复核”不是“已证伪”，经验过期也不自动取消项目要求。详细字段和包格式见 [docs/DATA-FORMAT.md](docs/DATA-FORMAT.md)。

### 6.5 卸载、备份与恢复

此版页面尚无删除按钮，避免误删。停止服务后，可把特定 `data_root/libraries/包ID/版本/` 移到库外备份目录；重启后就不再显示。不要删除仍被项目结论引用的来源而不保留副本。

备份包括：本机配置、原始知识目录、安装包目录、项目总账与差异、黑板、成果及外部原书来源。单独备份公开本体不能恢复私人积累。`runtime.json` 是可重建的运行信息，不是资料库。

## 7. 技能安装和对话接续

`skills/architecture-collaboration/` 是独立可分发的技能目录。可按所用智能体工具的技能安装方式，把这个完整目录放到其个人技能目录。以支持该约定的 Codex 为例，放到个人 `~/.codex/skills/architecture-collaboration/`；若已有同名技能，先备份和比较，不要覆盖个人修改。

技能自动发现取决于使用的客户端及其设置。本仓库不会通过平台偷偷修改全局技能配置，也不会保证每次对话都强制调用技能。推进跨领域设计、恢复项目、复核与迭代时适用；简单出图、单项编辑按实际需要轻量执行。

首次接续要把**本机配置或项目黑板位置**告诉对话助手。技能自身不携带你的资料，不会凭技能名称知道你的项目目录。建议对话说明：

> 使用 architecture-collaboration。项目入口是我本机的绑定配置，先读取当前完整总账、近期差异与黑板；遵守当前阶段，只在已有授权范围推进。外接包是参考资料，不能自动变成当前项目决定。

本体升级与个人技能升级是两个动作：平台运行新代码不会自动覆盖全局安装的技能；反过来，更新技能也不会自动改变平台项目数据。

## 8. 原有工作台与迁移

### 8.1 本轮已经做的整理

- 建立独立可发布的 `core/`，去除单一项目名称、固定条目数和机器路径。
- 本人配置、来源索引、整理清单、安装包与运行状态放到旁边的 `local-data/`。
- 原有总账、黑板、知识目录、模型和成果**原位保留**，通过绑定映射，避免直接搬目录导致证据和旧程序断链。
- 现有文本知识目录通过适配器实时读取，不复制一套竞争性完成状态。
- 旧工作台保留原源码、`.studio-data`、案例和工具链；在新页显示独立兼容入口。
- 记录整理时的源文件大小、散列和位置，便于以后逐步迁移。

这叫“无损归类与绑定整理”，不是宣称已完成所有物理搬迁。`local-data` 中部分子目录是指向原权威数据的索引，并非原文件全集。

### 8.2 为什么旧工作台没整体塞进本体

旧工程的项目简报、课程截图研究、预置案例、场地数据、生成方案默认值与若干路径散在源码中，排除数据库仍可能泄漏私人材料；直接复制会让别人的全新安装误以为这些是自己的项目事实。此版保留兼容，不冒充已经通用化。

旧工作台仍按它原来的方式运行，可能需要 Node、建模软件或其他依赖。新平台不自动启动它，不替它迁移模型API密钥，不接管旧对话及写模型接口。它的既有功能和许可由原工程单独说明。

### 8.3 后续全面通用化的路径

1. 列出旧工程所有动态导入、数据源、默认项目和写入位置。
2. 将项目简报、研究包、案例、角色与场地参数迁到有版本的数据适配层。
3. 用虚构示例替代硬编码私人默认值，并逐模块验证无资料安装。
4. 模型/出图/环境工具做独立适配器，执行契约与权限明确。
5. 对比迁移前后相同输入的功能与成果，保留回退。
6. 达到等价性后，才宣布旧模块已并入通用发行物。

这些是后续路线，不是本版已实现能力；不会因为写在路线中就算验收完成。

## 9. 升级和回退

详细步骤见 [docs/UPGRADE.md](docs/UPGRADE.md)。基本原则：**更新本体，不覆盖外部数据；涉及数据格式变化时先备份、明确迁移、再切换。**

当前有三条版本线：

| 对象 | 当前格式 | 升级含义 |
| --- | --- | --- |
| 本体 | 0.3.1 | Python/页面/技能与工具的实现版本 |
| 配置 | schemaVersion=1 | 目录、文件和接入方式的约定 |
| 资料包 | ac-library-pack/v1 + 包自身version | 格式版本与条目内容版本分开 |

项目总账的 `version` 是项目需求基线版本，模型的 `designRevision` 是成果版本，二者不随本体升级自动改号。资料包新版本也不自动判定旧项目证据失效；需按适用性做影响判断。

升级推荐：停服务 → 备份外部数据与配置 → 在新目录解包/检出新本体 → 阅读CHANGELOG → 跑测试与演示 → 用原本机配置连接 → 核对要求数、关键ID、包散列和成果入口 → 再切换常用启动入口。

回退：停止新版，用旧版本体连接备份配置及其兼容的数据。未来若做不可逆数据迁移，不能只回退程序而继续读被改过的数据。本版没有后台自动更新器、远程拉包或自动格式迁移器。

## 10. 测试与发布到GitHub

### 10.1 本地检查

在仓库根目录运行：

```sh
python -m unittest discover -s tests -v
python tools/release_check.py
python tools/release_check.py --manifest
```

测试覆盖包完整性、非法ID、私有导出确认、并发重复安装、冲突不覆盖、跨库导出再安装及实时文本映射。发布检查列出文件并扫描常见个人路径、密钥标记、二进制成果及本机配置；扫描是启发式，不证明所有隐私与版权均已排除。

还应手动打开虚构演示、安装示例包、搜索条目、选定导出、换一个外部数据目录再安装，确认没有依赖作者电脑。当前版本额外完成过本机真实绑定与浏览器功能检查，具体结果见 [docs/VALIDATION.md](docs/VALIDATION.md)。

### 10.2 只上传本体

1. 进入 `core/`，确认 README、示例、代码、技能和文档在此层。
2. 查看 `NOTICE.md`，决定仓库所有者希望采用的发布许可证；本次没有擅自指定整个平台MIT许可。
3. 运行检查，查看 `release-manifest.json`。
4. **在 `core/` 内建立仓库**，不要在本地装配区或原建筑项目根目录执行全量提交。
5. `git status` 与暂存差异中不应出现个人配置、`local-data`、知识原文、模型、原书、截图或旧私有数据库。
6. 再由所有者创建远程仓库、推送。

示例命令（本项目没有替你执行推送）：

```sh
git init
git add .
git diff --cached --stat
git status
git commit -m "Prepare architecture collaboration platform"
```

`.gitignore` 只防止未追踪文件被误加入，不能移除已经进入提交历史的秘密。`local-data` 应放在仓库外，不能只靠忽略规则保护。

此轮没有创建远程GitHub仓库、没有推送、没有公开任何个人库。

## 11. 限制、故障与后续扩展

### 已实现与未实现

| 已实现 | 本版未实现 |
| --- | --- |
| 本机配置化项目映射、持续要求检索 | 多用户权限、公网服务、实时代理监控 |
| 外部文本目录、资料包预览/安装/导出 | PDF全文解析、原书打包、跨库自动学习 |
| 版本与原作者链保留、安装不覆盖 | 作者身份签名、远程市场、自动更新 |
| 外部数据目录、示例初始化、发布检查 | 旧工作台全部模块通用化、数据库自动合并 |
| 技能及总账检查工具分发 | IFC/Revit仿真、碳排计算、规范定审 |

### 常见问题

**页面打不开**：检查终端是否仍运行、端口是否匹配、Python是否≥3.11；默认地址必须用 `127.0.0.1`，不是 `localhost`。地址与Host检查有意一致。

**启动时报找不到文件**：配置路径相对配置文件目录解析。核对 `project_root` 和其中的总账路径；本机绑定不能直接搬给另一个人。

**页面出现读取失败**：源文件可能正在被非原子写入、格式损坏或被移动。修复后下一轮读取会恢复；平台不会替你覆盖文件。频繁写入者宜先写临时文件再原子替换。

**安装被拒绝**：检查包格式、大小、SHA256和ID。不要手工改正文后沿用旧散列；由工具重新打包，内容变化使用新版本。

**同版本冲突**：这是保护原有经验的设计；使用新包版本，不覆盖旧内容。

**旧工作台链接无法打开**：它是独立进程，需按原工程方式启动；此页面的链接不是健康检查，也不说明旧工程正在运行。

**源目录有文件但没显示**：适配器只读第一层、支持的文本扩展名、UTF-8且≤128KiB文件；PDF、图片、嵌套目录和软链接没有被自动吸收。

**导出的条目仍标private/unverified**：这是保留原身份，不是导出失败。分享授权、阅读状态和验证状态互不替代。

### 扩展顺序建议

先把资料与项目接口稳定下来，再按真实问题增加适配器。规范信息检查、几何、工程计算、体验与用户反馈各自保留证据边界；AI生成的规则需要验证，不能由语言总结替代真实工具结果。大规模检索、多专业图谱、调度框架、模型写入等不属于“装了就自动更聪明”的功能。

扩展应有明确输入版本、读写范围、执行前检查、写后读回、失败与回退条件。重要变化回到总账和当前项目，不在平台角落另维护一套完成状态。


## 工作轨迹：模块关系与回放

新增“工作轨迹”导航，可按事件顺序播放、闪动当前连接、查看节点累计到达次数和证据。项目配置的可选 `run_log` 指向外部日志JSON；未配置时显示未绑定。历史重建与事件记录明确区分，不推定未采集的耗时、调用次数或并行关系。详见 [事件格式和语义](docs/RUN-LOG.md)。平台只读映射日志，不自动监听代理，也不驱动任务。日志仍属于个人数据，不随本体上传。


## v0.3.0：经验召回与实际反馈

重要设计建议先按当前问题检索外部经验，再写清预期改变及观察方式。结果偏离预期或影响关键接口时返回相关专家；无需为普通编辑启动完整循环。经验带来源、条件和反例，试用不等于跨项目学会。详见 [学习约定](skills/architecture-collaboration/references/learning.md)。

“工作轨迹”的事件可绑定文本、图片及模型证据，点击即可检查具体建议、实际成果及经验，显示当前文件散列及变化。详见 [事件与证据格式](docs/RUN-LOG.md)。平台只是映射：操作仍在对话，事件由执行者记录，尚无自动代理监听或全量Token分摊。项目材料留在外部数据；本体无需作者原书或私人项目即可运行。

整体深化可采用[有边界的设计循环](skills/architecture-collaboration/references/execution.md)：绑定用户目标、持续要求版本及实际时间/投入上限，按真实总图与空间、独立批评、总控自评、修改与复核接续。恢复不重置窗口；“可讨论”不等于原目标达到。达到目标或约定上限时保存实际结果与未闭合差距。该机制由技能指导当前操作者执行，平台映射已记录的事件，不提供后台自动设计或预算硬停；普通小改仍使用轻量路径。

## v0.3.1：先比较总体，再按收益协作

总体方向未定时，用少量关系草图、体量和关键剖面比较不同组织，再选定深化；用户已明确方向或只改局部时直接沿用。后续反复修接口却不能改善整体关系时，回查骨架和问题定义。相关规则见[执行约定](skills/architecture-collaboration/references/execution.md)。

将决定布局是否成立的道路/车库接入、疏散安全终点及适用救援到达等条件前置。未知条件记录假设及布局影响，后续工程专项保留真实边界；形态获认可不代表整体规范成立，详见[核验约定](skills/architecture-collaboration/references/verification.md)。

默认总控集中推进，独立任务有明确收益再并发，关键节点保留必要独立复核，可靠程序负责计量与导出。时间、费用与质量分别评价，经验增长通过下次任务中的决策变化和返工验证。此补丁是操作者执行规则，没有新增后台调度、自动学习或硬预算能力；效果尚需实际任务检验。升级不改变现有配置、总账或资料包格式，个人经验继续外接。变更与验收示例见[投入控制说明](docs/EFFICIENCY-PATCH.md)。
